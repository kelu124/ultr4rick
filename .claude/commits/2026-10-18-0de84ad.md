# python: Ultr4rick() reads firmware and library versions at connection

- **Commit:** 0de84ad59ddef36996c6ec408a60f75f72148a6c (branch main, at the maintainer's request)
- **Date:** 2026-10-18
- **Files:** python/ultr4rick/device.py, python/ultr4rick/version.yaml
- **Versions:** firmware unchanged, python 0.1.11 -> 0.1.12

## Why
The maintainer wants every device connection to come back with two strings: the firmware version and the Python
library version.

## What changed
- `Ultr4rick.__init__` calls `version()` after opening the port and retries once if no version was parsed (the
  first reply after open can be lost or partial).
- New attributes `firmware_version` (e.g. `"0.1.15"`, `"unknown"` if unparsed) and `library_version`
  (`ultr4rick.__version__`), printed as `Firmware <fw> - library <lib>` even when `verbose=False`.
- New `versions()` returns `(firmware_version, library_version)`.
- Works on both firmware builds: both print `ultr4rick firmware v<ver>` for `version`.

## Verification
Fake serial port: the parsed reply gives `('0.1.15', '0.1.12')` (both `str`); a silent port gives
`('unknown', '0.1.12')` after the retry. **Not verified on hardware**: the board was not enumerated on USB.
