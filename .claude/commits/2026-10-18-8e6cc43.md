## Why
The maintainer asked for a docs folder (intro for newcomers, setup and first acquisitions, firmware overview, Python
library, repository map), for every code change to be reflected there, and for the docs to be versioned like the
firmware and Python.

## What changed
- `docs/` pages written from the sources (firmware 0.1.15, Python 0.1.13): command replies from `main_dsp.c`/`main.c`,
  header from `dsp.py` `HEADER`, DSP stages from `dsp.c`, LED stages from `led.h`, mux element table from the
  `MUX.kicad_sch` netlist.
- `docs/version.yaml` (`version`, `changes`, `firmware`, `python` checked-against) and `docs/CHANGELOG.md`.
- New skill `ultr4rick-docs`: code-area -> page table, same-commit rule, docs patch bump, style.
- `ultr4rick-versioning` now has three components; `ultr4rick-changelog` workflow has a docs step and allows
  commits that bump neither firmware nor Python (docs bumps included) straight to main; CLAUDE.md and README.md
  point to docs/ and the licenses.
