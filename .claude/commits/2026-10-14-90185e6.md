## Why
`embarke/` is a copy of the pic0rick 0.1.11 firmware. It had the pic0rick PMOD pin map (P+/P-/PDAMP/OE on 11/12/16/17,
DAC SPI on 13-15, MUX on 18-21/28) and built for RP2040/RP2350A. The target is the RP2350B v2 board, and it should
identify as Ultr4rick.

## What changed
- Pin map checked against the `hardware_v2` netlist (`kicad-cli sch export netlist`); see `embarke/PINMAP.md`.
- `boards/embarke.h`: RP2350B, 12 MHz XOSC, W25Q128 16 MiB, I2C0 24/25, SPI1 26/27. CMake forces
  `PICO_BOARD=embarke`, `rp2350-arm-s`; the MUX option is gone (always built); DSP option kept.
- Pulser: one PIO1 SM on GPIO22/23 = {A,B}. States: 0 off, 1 (A) negative, 2 (B) positive, 3 damping.
  The timing/overhead model is unchanged (8 ns tick, 5-tick overhead).
- The MCP4812 SCK/SDI and the MAX14866 CLK/DIN share the same nets (GPIO26/27). Both now use hardware spi1
  (`hw/spi_bus.c`, mode 0, 2 MHz); the MAX14866 PIO bit-bang was removed. A mux write shifts 16 bits then
  pulses nLE once (the old leading nLE pulse would latch leftover DAC bits).
- stdio build: `u4rk_acquisition_init()` moved before the USB-connect wait so A/B are low from boot.
- Identity: USB strings Ultr4rick / "Ultr4rick RP2350B Signal Processor" / U4RK0001, frame magic P0RK -> U4RK,
  `version`/`status` say ultr4rick, `status` package RP2350B.
- I2C0 and uSD pins are defined but not driven.
- Hardware finding: on U2 (MCP4725) SDA/SCL are swapped against the net names (logged in TODO.md).

## Verification
- `./build.sh -DPICO_TOOLCHAIN_PATH=/usr`: both variants build with no warnings (stdio 82 KB UF2, DSP 211 KB UF2).
- `picotool info`: family rp2350-arm-s, pico_board embarke, boot2_w25q080, version 0.1.12; the DSP pin list shows
  GPIO 0-10 ADC, 11 CS_DAC, 21 nLE, 22/23 pulser A/B, 26/27 SPI1, 28/29 SET/CLR.
- Not flashed or tested on hardware.
